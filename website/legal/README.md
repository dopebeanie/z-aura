## Что готово

- `templates/terms.html`: условия использования, MIT для оригинального кода и отдельные лицензии сторонних компонентов, ограничения и безопасная работа.
- `templates/privacy.html`: локальные данные/журналы, обработка трафика сторонним движком, пользовательские HTTPS-проверки, always-on Presence и видимость имени пользовательского профиля, удаление и обращения.
- `templates/index.html` и `templates/page.html`: главная страница, общая оболочка и навигация.
- `styles.css`: статическое оформление без внешних шрифтов, скриптов, форм, trackers или зависимостей desktop-приложения.
- `site.config.example.json`: **пустая конфигурация**, не содержащая выдуманного домена, владельца или контакта.
- `scripts/build-discord-legal-site.mjs`: отдельная сборка сайта, не связанная с загрузкой/запуском `Z-Aura.exe`.

## Окончательная сборка и локальный просмотр

Из корня проекта:

```powershell
node scripts/build-discord-legal-site.mjs --config website/legal/site.config.json
```

Откройте `artifacts/discord-legal-site/index.html`, `terms.html` и `privacy.html`. Итоговые страницы не имеют отметки «Черновик», а `portal-links.json` содержит целевые Terms/Privacy URL и статус `built-not-yet-deployed-or-discord-verified`. Это не подтверждение публикации.

Пакет для загрузки: `artifacts/Z-Aura-GitHub-Pages.zip`. В нём только пять файлов сайта в корне, без EXE, конфигурации сборки, журналов и остальных исходников. **Распакуйте ZIP и загрузите файлы**, не сам ZIP как содержимое сайта.

Если нужен отдельный черновой просмотр, не перезаписывайте окончательную сборку:

```powershell
node scripts/build-discord-legal-site.mjs --draft --config website/legal/site.config.json --out artifacts/discord-legal-site-draft
```

Черновые страницы помечены; `portal-links.json` в них содержит `null` вместо URL. Не публикуйте черновик вместо окончательных документов.

## Подготовка к публикации

1. Используйте уже заполненный `website/legal/site.config.json`; пустой `site.config.example.json` оставлен как образец для другой конфигурации.
2. При последующих изменениях проверьте сведения и заново утвердите редакцию:
   - `ownerName`: реальное имя ответственного владельца/организации, которое допустимо публично указать.
   - `contactUrl`: действующий публичный `mailto:...` или HTTPS-адрес канала связи для обращений. Не публикуйте секреты. Если это публичный issue tracker, предусмотрите непубличный канал для чувствительных запросов.
   - `siteUrl`: окончательный публичный HTTPS-адрес корня сайта, включая подкаталог, если он нужен. Адрес должен принадлежать вам/вашему проекту; синтаксическая проверка сборки не доказывает владение или доступность.
   - `hostingDisclosure`: название провайдера, технические данные запросов/журналов, правила/сроки хранения и URL его политики. Проверьте фактическую конфигурацию; не обещайте отсутствие инфраструктурных логов без проверки.
   - `effectiveDate`: дата утверждённой редакции `YYYY-MM-DD`.
   - `publicationApproved`: `true` **только после** проверки документов владельцем, при необходимости юристом.
3. Соберите окончательный сайт:

```powershell
node scripts/build-discord-legal-site.mjs --config website/legal/site.config.json
```

При неполной конфигурации/отсутствии утверждения сборка останавливается. В production-режиме запрещены HTTP, URL с credentials, очевидные example/invalid/test-домены. Это проверки конфигурации, а не юридическое одобрение или тест хостинга.

## Хостинг и ссылки

Выбранный хостинг — **GitHub Pages**, целевой адрес предоставлен владельцем: `https://dopebeanie.github.io/cl3j1hdh7dbb2dzx/`. Готовые пять файлов из `artifacts/discord-legal-site` (или распакованного ZIP) можно разместить в корне репозитория `dopebeanie/cl3j1hdh7dbb2dzx`. В Settings → Pages выберите публикацию из нужной ветки/корневой папки (например, `main` / `/ (root)`, если файлы загружены туда) либо настройте соответствующий GitHub Actions deploy. **Автоматического deploy, создания аккаунта/домена и изменения Developer Portal скрипт не делает.** Не публикуйте весь проект, `artifacts`, `data`, EXE, журналы или секреты ради этих страниц. Backend не нужен.

Целевые ссылки после размещения: `https://dopebeanie.github.io/cl3j1hdh7dbb2dzx/terms.html` и `https://dopebeanie.github.io/cl3j1hdh7dbb2dzx/privacy.html`. Пока они отвечают 404, использовать их в Portal как готовые документы нельзя.

После публикации откройте реальные `terms.html` и `privacy.html` без авторизации, проверьте HTTPS, HTTP 200, текст, контакт и мобильную навигацию. Скопируйте два окончательных URL из `portal-links.json` в соответствующие поля Discord. Статус файла специально не называет сайт deployed/verified: это нужно проверить отдельно.

`Interactions Endpoint URL` и `Linked Roles Verification URL` остаются пустыми для текущего Rich Presence-only приложения. Статический хостинг не реализует подписанные POST-взаимодействия или OAuth2 для ролей. Если понадобятся эти функции, сначала разработайте настоящий backend и обновите политику данных, а не указывайте ссылку на обычную HTML-страницу.

Полная инструкция и официальные источники: `docs/DISCORD-PORTAL-URLS.md`.
