# «Помочь с подключением» — DNS / hosts

## Что добавлено

Нативный мастер в **Обзоре**, **Диагностике** и **Ctrl+K → «Помочь с подключением»**.
Ничего не применяется автоматически при запуске, выборе профиля или включении proxy.

1. **Проверка причины.** Выбор Discord, Telegram, GitHub, Roblox или YouTube.
   Показывает выбранный и реально запущенный GUI-профиль, состояние GUI-движка,
   количество других winws/winws2 и состояние службы (только чтение).
   По нажатию проверяет системный DNS, TCP/443 и TLS с настоящей проверкой сертификата
   сервиса; сравнивает обычный маршрут и до трёх IP образца на проверяемый домен.
   Параллельные проверки имеют бюджет 8 секунд. Сторонние DNS/DoH не используются.
   Успех pinned-TLS при неуспешном обычном маршруте — **возможная** проблема DNS/маршрута,
   не доказательство подмены и не обещание исправления DPI.
2. **Понятное исправление.** «Показать изменения» доступно после проверки.
   Предпросмотр показывает только выбранный набор, сохраняемый ранее блок Z-Aura,
   точные IP/домены и пропущенные конфликты. Явное согласие с риском устаревших IP
   требуется даже если диагностика не подтвердила DNS-причину.
   YouTube диагностируется, но кнопка добавления недоступна: в образце нет его записей.
3. **Применение и повторная проверка.** Windows запускает отдельный режим-помощник
   того же EXE через стандартное `runas`/UAC. Перед записью повторно проверяется SHA-256
   просмотренного файла. Делается новая проверенная резервная копия, затем замена
   через Windows ReplaceFile; ACL целевого файла сохраняется. Очищается локальный
   DNS-кэш через dnsapi; ошибка очистки показывается отдельно от успешной записи.
   После успеха запускается повторная DNS/TLS-проверка; доступность media/voice этим
   не подтверждается. Операция записи не прерывается закрытием диалога.

**Обычных повышенных прав администратора достаточно**, если доступ не запрещён ACL,
read-only, политиками/защитным ПО. Не нужны SYSTEM/TrustedInstaller, смена владельца,
отключение Defender или обход политик. При отказе мастер объясняет ограничение.
Текущий production EXE, как и раньше, имеет `requireAdministrator` для WinDivert;
весь GUI **не был переведён на asInvoker**. Если GUI уже повышен, Windows может не
показывать второй UAC. Отдельный helper не запускает GUI, Presence, proxy или службу.

## Сохранение и откат

- Цель помощника фиксирована: Windows SystemDirectory + `drivers\etc\hosts`.
  CLI принимает только действие, известные ID наборов и ожидаемый hash; не принимает
  пути назначения, полный файл, scripts, IP/домены из внешнего запроса или секреты.
- Добавляется блок `# Z-Aura BEGIN hosts-v1 …` / `# Z-Aura END hosts-v1` с SHA-256 тела.
  Только известные встроенные пары, канонический формат и неповреждённый hash допускаются
  для обновления/отката. При ручной правке блока требуется ручной разбор; удаления нет.
- Чужие записи, aliases, регистр, комментарии, BOM/кодировка и существующие LF/CRLF
  сохраняются. Формат без BOM сохраняется побайтно, включая legacy-комментарии.
  UTF-8 BOM и UTF-16 LE/BE поддерживаются; неоднозначные/UTF-32/слишком большие файлы
  отклоняются. Вставленный разделитель при отсутствии финальной новой строки учитывается.
- Чужая запись того же домена с отличающимся набором IP — весь домен пропускается,
  конфликт показывается. Даже совпадающие чужие записи не становятся нашей собственностью.
- Копии `hosts.zaura-backup-<UTC>-<GUID>.bak` находятся **рядом с системным hosts**,
  в той же защищённой папке. В ней хранится полный исходный файл, а не telemetry.
  Создание только `CreateNew`, `Flush(true)` и сверка SHA-256; существующие копии не заменяются.
- Откат удаляет **только проверенный блок Z-Aura**, не восстанавливает весь старый файл.
  Изменения других приложений после установки остаются. Чужие записи не удаляются.
- Reparse/symlink-цепочки, hardlinks, read-only, ошибки прав/блокировки не обходятся.
  Mutex сериализует наши helpers. Hash проверяется перед подготовкой и непосредственно
  перед ReplaceFile; это не транзакционный CAS для стороннего редактора, который заменит
  файл в самом последнем промежутке. Одновременное редактирование hosts нужно избегать.
- Резервные копии не очищаются автоматически. Не публикуйте их: hosts может содержать
  внутренние имена/локальные адреса. Отдельного consent/deploy правовых страниц не выполнено.

## Код и проверка

- `Core/HostsRepair.cs`: catalog, byte-preserving plan, guarded fixed-path helper.
- `Core/ConnectionDiagnostics.cs`: bounded cancellable DNS/TLS, injectable offline fixtures.
- `UI/ConnectionHelp.cs`: три стадии, preview/consent, UAC cancellation, repeat checks/rollback.
- `Core/HostsRepairTests.cs`, `UI/UiSmoke.cs`, `tests/hosts-repair.test.mjs`: сохранность,
  форматы, конфликты, stale hash, ACL/ReplaceFile, hardlink refusal, UAC cancellation fixture,
  выбор набора, unsupported YouTube, повреждённый блок и темы/accessibility.
- `scripts/import-hosts-sample.mjs`: только явный локальный импорт на машине разработчика,
  не startup/build download. Источник остаётся нетронутым.

Автотесты **не изменяют настоящий Windows hosts, не выполняют настоящий UAC/DNS flush
или внешние DNS/TLS-запросы**. Файловые операции только на собственных GUID-fixtures;
проверки сети/UAC инъецированы. Реальное применение/откат через production launcher,
отказ/отмена настоящего UAC, защитное ПО, symlink и чистая Windows требуют отдельного
ручного acceptance. Signing и review распространения остаются открытыми.

Сборка без изменения прежних EXE:

```powershell
node scripts/build-portable.mjs --output-dir artifacts/portable-hosts-helper
node scripts/verify-portable.mjs --artifact-dir artifacts/portable-hosts-helper
```

Проверка пользователем: **Обзор → Помочь с подключением → выбрать сервис → Проверить →
Показать изменения → прочитать конфликт/список → подтвердить → Применить через Windows**.
Для отката: **Отменить изменения Z-Aura → просмотреть → подтвердить → Применить**.
Если у пользователя нет админ-прав, приложение не пытается их обойти.

Z-Aura — не VPN и не гарантия подключения/анонимности. Новости: [@zaurafork](https://t.me/zaurafork).
